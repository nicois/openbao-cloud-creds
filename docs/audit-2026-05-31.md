# Repository Audit — 2026-05-31

Ranked list of the 10 highest-value improvements, from a full-repo audit. Items
1–3 are **verified correctness bugs** (reproductions confirmed against the code);
the rest are evidence-backed maintainability/coverage/CI gaps. None conflicts
with the deliberate per-plugin-module isolation in `docs/decisions.md`.

## 1. Stable `error_code` contract defined but never used (correctness/security, M) — [RESOLVED 2026-05-31]
**Resolved:** added `credenvelope.ErrorResponse(code, msg, …)` which embeds the stable code in the client-visible message as `"<code>: <message>"` (verified empirically that OpenBao drops Data side-channels on error responses, so the code must ride in the message string). All 10 plugins' credential-issuance error sites now use it; each has a `TestCredsIssue_RoleNotFound_HasErrorCode` (or OCI's `TestCredsRead_RoleNotFound_HasErrorCode`) asserting the prefix via `resp.Error().Error()`.

`pkg/credenvelope/errors.go` defines `PluginError`/`ErrorCode` with 10 codes, but
no plugin uses `NewError`/`PluginError`. Handlers jam the code into free text
instead — e.g. `credential-do/path_creds.go:50` `logical.ErrorResponse("role_not_found: ...")`,
`:181` `fmt.Errorf("upstream_auth_failed: ...")`. `path_creds.go` across plugins:
49 `fmt.Errorf`, 0 `NewError`. CLAUDE.md/techrfc promise a machine-parseable
`error_code` on every error response; today it's documentation-only. **Fix:**
helper in `pkg/credenvelope` that renders `PluginError` → `logical.ErrorResponse`
with a structured `error_code` Data field; convert handlers.

## 2. [VERIFIED BUG] Per-node metrics double-count (correctness, M) — [RESOLVED 2026-05-31]
**Resolved:** `MergeEntity` now skips this node's own flushed storage key (`pkg/metrics/access.go`), so the live node is counted once via in-memory entries and remote nodes via storage. Regression: `TestMergeEntity_NoDoubleCountOnLocalNode`.

`pkg/metrics/access.go`: `Flush` writes the full running `AccessCount` to storage
but never resets `t.entries`. `MergeEntity` sums the flushed storage value AND the
same node's live in-memory entries — so any node that both issues and serves the
`metrics/entity` query double-counts its own accesses. Tests miss it by querying
via a *fresh* tracker that never recorded locally (`access_test.go`). Inflated
counts make a stale entity look active → never reclaimed. **Fix:** track a
flushed baseline and merge only the delta, or skip the local node's storage key
when also counting local memory. Add a single-tracker record+flush+merge test.

## 3. [VERIFIED BUG] `ListStaleEntities` mis-parses entity IDs (correctness, M) — [RESOLVED 2026-05-31]
**Resolved:** metrics storage-key segments are now `url.PathEscape`d on write and `url.PathUnescape`d on parse (all three key sites in `pkg/metrics/access.go`), so a `set/minter` entity ID survives as one segment and stale-entity bucketing is per-minter. Regression: `TestListStaleEntities_EntityIDWithSlash`.

Every plugin records `RecordAccess(setName+"/"+minterID, role, now)`, so the flush
key is `metrics/<set>/<minter>/<role>/<node>`. `ListStaleEntities` does
`SplitN(trimmed, "/", 3)` and takes `parts[0]` (access.go:18–22) → it treats the
**set** as the entity, collapsing every minter in a set into one staleness bucket.
One active minter hides every stale sibling — exactly the failure `entity_id`
keying was meant to prevent (decisions.md). Tests only use slash-free IDs. **Fix:**
treat entityID as opaque (don't split on `/`); reserve a different separator or
length-prefix. Add a test with a `set/minter` entity ID.

## 4. Reconciler owner-tag delete-safety invariant has no test (test-coverage/security, M) — [RESOLVED 2026-05-31]
**Resolved:** added `pkg/reconciler` core guard (`TestRun_OnlyDeletesListedOrphans`) plus a per-plugin `TestReconcile_NeverDeletesForeignEntity` on all 6 cloud-lister plugins (do, upcloud, exoscale, azure, vultr, akamai) — each injects a foreign-named upstream entity, runs a real deleting reconcile pass, and asserts it is never deleted nor counted as an orphan.

`pkg/reconciler/reconciler.go` deletes anything `ListTaggedEntities` returns that
isn't `IsKnown`; the `cloud-creds-` prefix filter is per-plugin
(`credential-do/reconciler_integration.go:25`). `reconciler_test.go` never asserts
that a non-prefixed/foreign entity is **never** deleted. CLAUDE.md calls this "the
load-bearing safety invariant" — the most dangerous path is untested. **Fix:**
per-plugin table test feeding mixed tagged/untagged entities, asserting only
tagged reach `DeleteEntity`; consider a reconciler-level prefix re-check (defense
in depth).

## 5. OCI/AWS reconcilers diverge from `pkg/reconciler`; manual path lacks the hold (maintainability/correctness, M–L)
AWS (`path_reconcile.go:31-83`) and OCI (`path_reconcile.go:33-138`) reimplement
reconciliation inline; OCI has dead code (`now := time.Now(); _ = now`) and no
`ConfirmationHold`. DO's interactive `pathReconcile` hardcodes `ConfirmationHold: 0`
while the worker uses `1h` — manual reconcile can delete a credential issued
seconds earlier, mid-flight. **Fix:** route OCI/AWS through `pkg/reconciler`
(extend for no-upstream-delete clouds); make `ConfirmationHold` consistent.

## 6. Worker errors and panics are silently swallowed (operability, S) — [RESOLVED 2026-05-31]
**Resolved:** `pkg/worker.Manager` now takes a `WithErrorHandler` functional option and wraps each tick in `invoke()` with `defer/recover`, converting panics to errors; all 10 plugins construct the manager with a handler that logs via `b.Logger().Warn` and increments `cloud_creds_worker_errors_total{cloud,worker}` (routed through each plugin's `emitCounter` helper). Tests: `TestWorker_ErrorHandlerInvokedOnError`, `TestWorker_PanicRecoveredAndReported`, `TestWorker_NilHandlerStillRecoversPanic`.

`pkg/worker/worker.go:86` `_ = w.fn(ctx)` discards every periodic worker's error —
no log, no metric. No `recover()`, so a worker panic crashes the plugin process.
A persistently failing reconciler/flush is invisible. **Fix:** pass a
logger/error-callback into `Manager`; log + emit `cloud_creds_worker_errors_total{worker}`;
add `defer recover()` in `run`.

## 7. Near-identical telemetry/workers/health-check duplicated ×10 (maintainability, M)
After normalizing package name + cloud string, `telemetry.go` collapses to ~3
variants (6 byte-identical); `workers.go`/`health_check.go`/`path_metrics.go`/
`reconciler_integration.go` repeat per plugin. Bugs #1/#2/#3 must be fixed in 10
places. **Do NOT** collapse the per-plugin modules (deliberate process-isolation,
decisions.md) — extract the genuinely identical helpers into `pkg/` (cloud as a
parameter), which the design already sanctions. **Fix:** move emit helpers into
`pkg/metrics`, worker registration + metrics query paths into `pkg/` helpers;
plugins keep their own module + `backend.go`.

## 8. `pkg/cloudconfig` is the lowest-covered package (test-coverage, S) — [RESOLVED 2026-05-31]
**Resolved:** added `pkg/cloudconfig/validation_test.go` with table tests for `ValidateSetName`, `ValidateRole`, and `DefaultConfig`; package coverage rose 55.6% → 97.2%.

`go test -cover`: cloudconfig **55.6%** (next lowest recovery 81%).
`ValidateSetName` 0.0%, `ValidateRole` 0.0%, `DefaultConfig` 0.0%;
`ValidateMinterSet` 95.2%. The name/role validators are config-load gatekeepers
(RSK-005: silent infinite-expiry minters rejected at load). **Fix:** table tests
for `ValidateSetName` (empty, bad chars, path-traversal), `ValidateRole`,
`DefaultConfig`.

## 9. No concurrency tests despite `-race` in CI (test-coverage, S–M) — [RESOLVED 2026-05-31]
**Resolved:** added `TestStateMachine_ConcurrentAccess` (50 goroutines × 200 iters mixing all StateMachine methods) in `pkg/recovery`, and `TestConcurrent_IssueDuringWorkerActivity` (8 concurrent issuers + 2 metrics readers via exported `HandleRequest`) in `credential-do`; both pass under `-race`, exercising the shared `b.mu` hot path that was previously dormant against the race detector.

No `t.Parallel`/`go func()`/`WaitGroup` in any `*_test.go`. CI runs `go test -race`
but nothing in plugin logic runs concurrently, so the detector is dormant against
the hot path (concurrent issue + worker mutation of `b.minterSets` + metric emit,
all under `b.mu`). `recovery.StateMachine` is mutex-guarded but never tested under
contention. **Fix:** concurrent stress test in `pkg/recovery`; per-plugin
issue-while-worker-flushes test.

## 10. CI gaps: no govulncheck, no coverage reporting, no-op lint step (CI/security, S) — [RESOLVED 2026-05-31]
**Resolved:** removed the dead `golangci-lint-action ... args: --help` step (the per-module loop is now the sole linter); added a hard-fail `govulncheck` job running per-module across all 17 modules; added `coverage.out` upload via `actions/upload-artifact@v4`. Baseline vulnerabilities cleared by bumping grpc (1.79.3), x/net (0.55.0), go-jose/v4 (4.1.4) and pinning CI to Go 1.26.3; govulncheck is clean across all modules.

`.github/workflows/ci.yml`: the `golangci-lint-action@v7` step uses `args: --help`
— it runs `--help`, not a lint; real linting is a separate manual loop, so the
action step is dead weight. `coverage.out` is produced but never uploaded or
thresholded. No `govulncheck` anywhere — no supply-chain CVE gate on 10 plugins
each linking a different cloud SDK (contradicts the blast-radius rationale in
decisions.md). **Fix:** add a `govulncheck ./...` job; upload/threshold coverage;
drop or fix the `--help` step.
