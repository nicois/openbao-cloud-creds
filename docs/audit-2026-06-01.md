## 1. Per-node metrics never persist — the cross-node design is unimplemented (correctness/data-loss, M)
Every plugin builds its access tracker with `metrics.NewInMemoryStore()` and a
hardcoded nodeID `"local"` (e.g. `credential-do/backend.go:66-67`); there is no
storage-backed `MetricsStore`. So the flush worker writes to an in-process map,
lost on reload and never shared across nodes — directly contradicting
`decisions.md` ("per-node-tagged keyspace flushed every 15m, merged across
nodes"). A reclamation job trusting `staleness_seconds`/`ListStaleEntities`
(which operate on a substrate never populated in prod) could delete an in-use
upstream entity. **Fix:** a `logical.Storage`-backed `MetricsStore` wired in each
Factory via `conf.StorageView`, plus a real per-node nodeID. (Implements an
existing decision; does not conflict with it.) → **Effort 3**

## 2. Akamai EdgeGrid signing omits the request-body hash (correctness/security, M) — [RESOLVED 2026-06-01]
**Resolved:** Akamai now buffers and hashes the real request body in EdgeGrid signing (with maxBodyHashBytes=131072 cap in `credential-akamai/edgegrid.go`); the cloud-fake now independently recomputes and validates the EG1-HMAC-SHA256 signature (`pkg/credenvelope/fakes/akamai_test.go`), so a body-hash regression causes a fake 401.

`credential-akamai/edgegrid.go:62-69` signs POST/PUT with the empty-body hash
(`hashBody(nil)`, comment: "real impl would buffer"). EG1-HMAC-SHA256 requires
the SHA256 of the actual body; the mint POST would be rejected by real Akamai.
Fakes don't validate signatures, so tests pass. **Fix:** buffer + hash the real
body (spec caps at 131072 bytes); make the fake validate the signature. → **Effort 1**

## 3. Reconciler `IsKnown` is O(N²) — a full storage List per upstream entity (performance, M)
`reconciler.Run` calls `IsKnown(entity.ID)` per listed entity (`reconciler.go:87`),
and each `IsKnown` does a fresh full `storage.List` + linear scan
(`credential-do/reconciler_integration.go:50-61`, same in akamai/azure/exoscale/
vultr/upcloud). N entities → N raft-backed Lists of ~N keys = O(N²). At 100k
creds the pass cannot complete within cadence; orphan cleanup starves. **Fix:**
List once per pass, build a `map[string]struct{}`, pass a set-backed registry. → **Effort 3**

## 4. Five of ten `error_code` constants are never emitted; upstream failures collapse to `internal` (operability, S–M)
`ErrUpstreamQuotaExceeded`/`ErrUpstreamTimeout`/`ErrEntityUnavailable`/
`ErrConsentRequired`/`ErrLeaseRevokeFailed` are never emitted; every issue-time
upstream failure returns `ErrInternal` ("upstream error: %v", e.g.
`credential-do/path_creds.go:69`). AWS computes a classification but only feeds
the state machine, not the envelope; OVH detects 429 but still returns
`ErrInternal`. Clients can't distinguish retryable (429/timeout) from fatal.
**Fix:** a shared `classifyUpstream(status, err) ErrorCode` used at each issue-error
site. → **Effort 2**

## 5. Raw upstream response bodies propagated into client-visible error messages (security/info-leak, S)
Azure/Akamai client errors embed the full upstream body (`azure_client.go:162`,
`akamai_client.go:78`), which flows verbatim into the client-facing `resp.Error()`
via `credenvelope.ErrorResponse`. Graph/Akamai bodies carry tenant IDs, app
object IDs, internal request IDs. **Fix:** log the body operator-side; return only
the classified code + a generic message to the client. → **Effort 2**

## 6. OCI returns a usable lease with TTL=0 for an overdue slot (correctness, S) — [RESOLVED 2026-06-01]
**Resolved:** OCI `freshestSlot` now skips overdue slots (NextRotationAt not after now) rather than serving a TTL=0 lease; when all slots are overdue it returns pool_exhausted. Honest-TTL invariant restored. Regression: `TestCredsRead_OverdueSlot_PoolExhausted`.

`credential-oci/path_creds.go:73-77` floors a lagging slot's TTL to 0 and still
serves it (`freshestSlot` only filters `State==slotActive`). Violates OCI's
"TTL is always honest" invariant exactly when rotation lags. **Fix:** skip overdue
slots (fall through to pool_exhausted) or floor TTL to a positive minimum +
trigger that slot's rotation on read. → **Effort 1**

## 7. No real-cloud integration coverage for 9 of 10 plugins; fakes don't validate auth (testing, M) — DEFERRED
CLAUDE.md documents `-tags=cloud_real` but no plugin has such a test; all tests
use fakes that assert envelope shape but not authentication — which is why #2/#4
went undetected. **Fix:** per-plugin `//go:build cloud_real` issue→use→revoke
smoke tests against dedicated accounts; make fakes validate the auth header.
**Deferred** (requires dedicated cloud test accounts + CI secrets; out of scope
for this batch).

## 8. No rate-limit/backoff; reconciler + health-check fan out unthrottled (correctness/performance, M)
No retry/backoff on transient upstream errors anywhere; a 429'd minter stays
`TransientFailing` and keeps being selected (`selectMinter` accepts
`TransientFailing`) → immediate re-hammer (thundering herd at scale). Reconciler
deletes back-to-back; health-check probes in a tight loop. **Fix:** bounded
retry-with-jitter on 429/5xx in the clients, and/or a short 429 cool-down state
so a throttled minter is briefly de-selected; throttle reconciler deletes. → **Effort 2**

## 9. No rotation/lifecycle for the long-lived minter credentials themselves (feature/security, L)
Minters (the crown-jewel long-lived cloud creds at rest) are stored verbatim and
never rotated; the only "rotation" is OCI slot rotation. Validation *allows*
rotation (overlapping-expiry rule) but nothing rotates them, and a never-expiring
minter satisfies the rule forever. Largest standing security exposure. **Fix:**
emit a `cloud_creds_minter_expiry_seconds` gauge + warn within the 7d gap; optional
self-rotation for clouds whose API can mint a successor. → **Effort 4**

## 10. Background workers run on `context.Background()`; no `Clean` teardown hook (correctness/robustness, S) — [RESOLVED 2026-06-01]
**Resolved:** All 10 plugins now wire `framework.Backend.Clean` → `stopWorkers` (which holds workerLifecycleMu → stopWorkersLocked → baseCancel) and derive the worker context from a backend base context (`baseCtx`, created at backend construction) instead of `context.Background()`. Per-plugin `TestBackend_CleanStopsWorkers` proves teardown; existing `TestBackend_startWorkersTwice` tests now implicitly cover the idempotent stop path.

All 10 plugins launch `go b.startWorkers(context.Background(), req.Storage)`
(`credential-do/path_config.go:102` etc.); no backend `Clean` hook wires
`stopWorkersLocked` to OpenBao teardown. On backend reload/unmount the worker
goroutines (reconciler hitting cloud APIs, flush) leak past backend life.
**Fix:** implement `framework.Backend.Clean` → `stopWorkersLocked`; derive the
worker context from a long-lived plugin context, not `context.Background()`. → **Effort 1**

---

### Overall health (auditor's verdict)
Strong: clean shared-package factoring, consistent envelope/recovery/worker
structure, the prior audit's correctness fixes are real, and the safety-first
reconciler (fail-closed hold, owner-tag guard, create-then-track compensation)
is well-built. The standouts holding it back from production-ready at the stated
100k scale are **#1** (the reclamation safety signal is silently disabled) and
**#3** (O(N²) reconciler); **#2** means one advertised plugin likely doesn't
authenticate against its real API. Test coverage is broad but fake-only (**#7**),
which is what let #2/#4 slip through.
